# T667 — Tests that grow with the app: fewer hand updates per release and per feature

Status: IN PROGRESS — slices 1–2 done (the guard is on, both scanners at 0); left (Claude): slices 3–8 of `app-integration/T667-audit.md` §4, listed under "What is left" below.

Source: owner 2026-11-11: "we need to also make the tests more expandable; right now they get progressively more
unwieldy ... a Fable task to improve the tests generally, to naturally grow with the app without too many hand
updates needed every time."

## Seen on build 27
- Tests pin section handles and counts that move with every atlas (line.test.ts, WaterMode.test.tsx; many pipeline
  pins moved by owner-approved changes).
- A frozen reference ("page v36" oracles) needs a hand-written amendment for each approved rule change.
- 13 pipeline tests compare with the live release and are red from build to promote.
- Tests that behave differently under fast-fail's no-build plugin, the chunked runner, or a fresh clone.
- 422 pipeline test files, 604 app test files; the full suites need chunking to fit in memory.

## Work
1. AUDIT (Fable, read-only): classify every test by what it is tied to (a fixed synthetic fixture; the live release;
   a pinned id/count from a build; a frozen reference; the environment) and count the hand edits each class cost
   over the last releases (git history of test files). Output: `handoff/PLAN/app-integration/T667-audit.md`.
2. DESIGN (same doc): rules for new tests and a migration plan, e.g. pins addressed by stable keys (water name, blue
   line + measure) resolved at run time, never raw handles; values that follow a release are generated by the one
   re-cut step (T666) and reviewed as a diff; invariants and properties over the whole release instead of sampled
   pins where a pin adds nothing; one small frozen synthetic release for logic tests; references re-cut by command,
   not amended by hand; one test-environment contract so every runner gives the same answer.
3. MIGRATE in slices, worst class first; each slice keeps the mutation tests that prove the check still bites.
4. A guard: a new test that pins a raw handle or reads the live tree outside the allowed helpers fails review.

## Acceptance
- A rebuild with no rule change needs zero hand edits to tests (re-cut by command only).
- An approved rule change needs one edit at the source and a reviewed diff, not per-test amendments.

Depends: T666. Size: L. Fable for audit and design (owner). Part of the closed-testing run.
