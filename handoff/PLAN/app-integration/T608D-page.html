The exact tests

  • Name: lower case, punctuation dropped, "(formerly)" dropped, one closing word of lake / lakes / L. / pond / ponds / reservoir dropped. Then the two must be equal, or the lake's name must appear as whole words inside a longer chart title. Of the 1,944 clean ids, 1,706 are equal and 238 are a name inside a longer title.
  • Position: the centre of the sheet's outline may be at most 100 m outside the lake's bounding box.
  • Size: the sheet outline's area must be between half and double the lake's area.
  • Watershed: the two watershed codes must be the same.
  • The limits are loose on purpose and catch only the odd ones: 2,086 of 2,095 name-verified ids sit at 0 m, and 1,970 are within 0.8 to 1.25 times the area.
Why the printed title matters. The Province filled in its "gazetted name" column and its sheet outline from the lake code. So those two cannot prove the code is right; they only repeat it. The title printed on the chart is the one thing that was not made from the code, which is why a match that agrees only on the name column (rule A7) goes to you.

What the current code does that breaks your rules

  • A code whose lakes are all unnamed is bound to every one of them with no review. Proposed: a proposal you accept (A3).
  • Unnamed ponds under a named lake's code ride along. Proposed: a proposal you accept (A2).
  • The stocking matcher falls back to "same name within 2,000 m", and counts one name inside another as a match ("Fish Lake" inside "Little Fish Lake"). Proposed: remove it. It is a silent fallback.
  • A code hit with no name support is still marked matched. Proposed: refused until you accept.
  • The stocking matcher stores a build-output id. Proposed: store the lake's durable id.

How the frozen match file works

  • One file per feature. Each row holds the source id, our lake id, the rule that proposed it, the evidence (names, metres, areas), and who accepted it and when.
  • The program writes proposals to a separate file. Only your accept moves a row into the frozen file.
  • The build and the app read the frozen file and never match anything themselves. An id not in the file shows nothing and goes on the proposal list.
  • A re-run never rewrites accepted rows. It only reports new ids, ids that vanished, and accepted rows whose evidence changed.
  • Refusals are rows too ("not a public lake"), so the same question is not asked every year.

Sample plan, about 160 looks (a few seconds each with the PDF beside the outline): 60 from the 1,706 with an equal title, 40 from the 238 with a name inside a longer title, 30 from the outer size bands, 20 with a name used by six or more lakes, the 10 largest lakes and every reservoir. Every review row is looked at one by one. If 160 clean looks show none wrong, the clean set is very likely under 2% wrong. One wrong: stop, tighten the rule, re-run, sample again.

Stocking matching is weaker than chart matching in two ways. There is no printed title, so the row's name may itself come from the code. And there is no outline, so there is no position or size test. The proposal is to spot-check clean rows harder (100 at random, every lake whose name is used six or more times, and the top 50 lakes by fish released), and to send a lake stocked for the first time to you once.

No real stocking rows were counted: GoFishBC refused one small request on 10 Nov 2026 (HTTP 403), and it was not retried.

How the feed would stay fresh

  • Once: fetch the whole history, run the matcher, you review, the match file is frozen. The release carries each lake's last stocked day (under 10 KB) so the map works offline.
  • Daily, on the worker: one request for the last 45 days. New rows are added and placed on their lake through the frozen match file.
  • A lake the match file does not know: not shown. It goes on a proposal list and you get an email. Never guessed, never dropped quietly.
  • A failed fetch: a failed run on the status page. Never an empty list.
  • Words in the app: "Last stocked 6 Nov 2026: 1,500 rainbow trout (catchable)", then "Stocking records as of 10 Nov 2026." After 3 days without a check: "Stocking records may be out of date." A lake with no record says "No stocking record", never "not stocked".
  • Cost: one outside request and one or two small writes a day. No added money on the current plan.

The GoFishBC data endpoint still answers: one request for 25 Oct to 10 Nov 2026 returned 29 rows, each with date, town, lake code, lake name, species, strain, stage, size and count.
