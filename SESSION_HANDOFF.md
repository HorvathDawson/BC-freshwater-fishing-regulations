## What changed this session (all in the working tree already)

This only changes *how* an already-visible polygon is styled — the per-layer logic deciding *whether* a polygon shows at all (`admin_visibility.json` / layer-menu toggles) is untouched.
- Implemented in `webapp/src/map/styles.ts`: added two shared constants near the top (after `LAND_ACCESS_COLOR_EXPR`) — `ADMIN_BORDER_MINZOOM = 11` and `ADMIN_BORDER_OPACITY = 0.35`. The aboriginal-lands line kept its `line-width` zoom interpolation but its lower bound was moved from z9 to `ADMIN_BORDER_MINZOOM` and its opacity flattened to the shared constant.
- **Mobile deliberately NOT touched** — user said webapp-only; mobile styling changes are happening on a separate mobile branch.

## What changed in a prior session (all in the working tree already)

### Bug fixes (found while investigating user-reported confusion)
- **Indigenous-territory advisory never actually merged into "Land Use."** The merge check compared `restriction_type` (which is just `"advisory"` at the data layer) against the text `"indigenous territory"` — a string that only ever appears in `rule_text`/`restriction_details`, never in `restriction_type`. The check was always false, so the advisory always fell through to a separate "Provincial Regulations" bucket. Fixed in both `webapp/src/components/InfoPanel.tsx` and `mobile/src/components/InfoPanel.tsx` to match on the stable `regulation_id === 'PROV_ABORIGINAL_LANDS_ADVISORY'` instead.
- **"Land Use / Land Use" duplicate header** in webapp — the group badge already said "Land Use," and the group label was *also* hardcoded to the literal string `"Land Use"`, so it rendered twice. Label blanked (badge already conveys it).

### Land-ownership/access redesign (iHunter-style: Private / Permission-Required / Restricted / General-Use Crown)
- **`data/fetch_data.py` — `fetch_overpass_land_access()`**: the raw Overpass query pulled in *any* closed way/relation tagged with a restrictive `access` value, regardless of what it actually was. Checked live: of 16,360 raw results, 91% were noise — 33% backyard/hotel swimming pools (`leisure=swimming_pool`), 58% completely unlabeled private parking lots (named "Impark", "Visitor Parking", "Diamond Parking," etc.). Now post-filtered to keep only `landuse=military`, `boundary=protected_area`, `leisure=nature_reserve`, `landuse=reservoir_watershed` (134 real rows: DND bases, watersheds, ecological reserves) — a 99%+ noise reduction. The hand-curated `_NAMED_RESTRICTED_AREAS` supplemental pass (Malcolm Knapp Research Forest) is exempt from this filter since it's not raw crowd-tagged data.
- **`data/fetch_data.py` — `fetch_parcel_fabric()`**: now dissolves `OWNER_TYPE='Private'` parcels into one merged polygon too, the same way Crown/Federal/etc. already were — no more 1.29M individual private parcel rows, just one more dissolved polygon in the same `{name}_crown` layer (now genuinely ~9 rows: 8 crown types + Private). This was a deliberate simplification the user chose over tiling all 1.29M individual boundaries (that route would've needed a whole new zoom-gating/simplification strategy and a much bigger PMTiles download — the dissolved-blob approach avoids all of that at the cost of not showing individual property lines, which wasn't wanted anyway).
- **`pipeline/enrichment/base_regulations.json`**: the old `LAND_ACCESS_NO` / `LAND_ACCESS_PRIVATE` / `LAND_ACCESS_CLOSED_OTHER` / `LAND_ACCESS_RESTRICTED` (4 regs, each keyed to a fine-grained OSM `access` tag) replaced with 2 clean regs keyed on the already-computed `restriction_level` (`LAND_ACCESS_CLOSED`, `LAND_ACCESS_RESTRICTED`), plus a new `LAND_OWNERSHIP_PRIVATE` targeting the dissolved Private ownership polygon (`admin_targets: [{"layer": "land_parcels_crown", "feature_id": "Private"}]` — reuses the existing generic admin-target matcher, no new assignment logic needed).
- **`pipeline/enrichment/base_reg_assigner.py`**: added `"land_parcels_crown": "land_parcels_crown"` to `_ADMIN_LAYER_MAP` (one line — the matcher was already fully generic).
- **webapp + mobile `InfoPanel.tsx`**: the "Land Use" section can independently accumulate up to 3 access-severity regs simultaneously (a reach can genuinely touch a closed watershed AND a private parcel AND sit near restricted land all at once) plus the indigenous advisory — showing all of them read as confusing near-duplicates. Now collapsed to **at most one** access-severity line (priority: closed > restricted > private) **plus** the indigenous line if present, never more.
- **webapp `Map.tsx` + `styles.ts`**: added a second, independent "Private Land" toggle in the layer menu alongside the existing "Crown / Public Land" one — both draw from the same `land_parcels_crown` tile source-layer, split into two style layers via a `name` property filter. Private renders in a new warm-brown color (`#8D6E63`), distinct from Crown's slate-blue and the red/amber restriction colors. `land_access` (restricted/closed) and `aboriginal_lands` (indigenous) remain always-visible, non-toggleable — unchanged, per explicit request.
- **Docs/comments updated** in `pipeline/atlas/freshwater_atlas.py`, `pipeline/tiles/tile_exporter.py` to reflect Private now living in the ownership layer.

### Water access points (piers/boat launches/fishing platforms)
- **Marina removed entirely**, at every level: `data/fetch_data.py`'s Overpass query no longer fetches `leisure=marina`; webapp/mobile icon creation, image registration, color entries, and `poi_type` match branches all removed; both platforms also add an explicit filter excluding `poi_type='marina'` so old cached tiles won't render it either. `pipeline/atlas/models.py`'s `poi_type` docstring updated.
- **Private-access points now filtered at fetch time**: `fetch_overpass_water_access()` drops any feature where `access` or `mooring` is `private`/`no` (e.g. a pier tagged `access=private, mooring=private` no longer gets written). **This is a data-level fix — it needs a fresh fetch of the `water_access_points` layer to take effect** (see "Still pending" below).
- **Icons replaced**: hand-drawn canvas glyphs (ambiguous wedge/lines/masts/hook shapes) swapped for real, verified icon paths vendored directly into `webapp/src/components/Map.tsx` (no new npm dependency, no runtime network call) — boat launch → Maki `slipway`, pier → MDI `pier`, fishing platform → MDI `fishing`, waterfall → Maki `waterfall`. Licensed BSD-3/CC0 (Maki) and Apache-2.0 (MDI), attributed in code comments.
- **Icons now grow with zoom** instead of a fixed size — webapp's `icon-size` and mobile's `circle-radius` both now zoom-interpolated (13→19).

### Basemap cleanup
- Removed the Protomaps basemap's generic `pois` symbol layer (post offices, shops, restaurants, etc.) from the webapp style — not relevant to a fishing-regulations app, just clutter. Place-name labels (`places_*` — cities/towns) were kept.
- **Trail/backcountry-road visibility fixed at zoom >15**: the custom `roads_other_early` overlay (which renders trails nicely from z11) was capped at `maxzoom: 15`, handing off to the basemap's native `roads_other` layer — whose actual line-width curve is `interpolate(exponential 1.6, zoom, 14→0px, 20→7px)`, i.e. **literally 0px wide at z14** and still under 1px through z16. The handoff happened at exactly the zoom where the native layer is most invisible. Fixed by extending the custom overlay to own the full zoom range (added width stops out to z20) and filtering the broken native `roads_other` layer out of the basemap entirely (no double-render). Labels were fine as-is and still hand off at z15 (protomaps' label layer uses a fixed text size, no broken width curve).

### Label rendering / collision priority (webapp only — mobile doesn't have polygon name labels ported yet, pre-existing gap)
- **Big lakes no longer lose label placement to swarms of small lakes**: added `symbol-sort-key: ['-', 0, ['get', 'area']]` to `lakes-label`, `wetlands-label`, `manmade-label` — lower sort key wins MapLibre's collision-placement race, so bigger/more important waterbodies are now placed (and win overlaps) before smaller ones. (Considered but deliberately did *not* do the alternative fix — precomputing a single "label point" per lake polygon to stop big lakes from showing their name multiple times across tiles — because the user correctly flagged that a single representative point might fall outside the viewport when zoomed into one corner of a huge lake, causing the name to disappear entirely. Not implemented; worth revisiting with a different approach if the multi-label-on-big-lakes issue comes up again.)
- **Waterbody names were losing collision priority to park/land-use names**: MapLibre's label-collision priority is decided by array order (later-added layers win). `createRegulationLayers()` used to bundle waterbody name labels in with the fills and return them all together, positioned *before* `createAdminLabelLayers()` (park/watershed/land-use names) in `Map.tsx` — so park/land-use labels always won. Fixed by splitting `createRegulationLayers()`'s return into `{ layers, labels }` (fills stay in their original position for correct paint z-stacking; `labels` — the waterbody names — now get spliced in *after* `createAdminLabelLayers()` in `Map.tsx`, so they win collisions instead).
- **Indigenous/land-access name labels delayed to minzoom 11** (webapp + mobile, both `admin_land_access-label` and `admin_aboriginal_lands-label`) — the colored fill/hatch overlay itself is unaffected and still shows earlier; only the text name was pushed back so it doesn't clutter lower zooms before the user is close enough to be near it.
