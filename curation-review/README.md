# curation-review: the owner's review tool

A local app where the OWNER checks every parsed catalogue entry against the book: that it was parsed right (T text,
R rules), that its rules land on the right water and extent (P place) and that the app's own answer agrees (A). An entry
signed off on all four is human-reviewed; it comes back for a re-check when its text, rules or extent change. It makes no
LLM calls and spends no credits. Review only: it writes one thing, a mark (`POST /api/marks`), plus in-season water matches
(`POST /api/inseason/matches`); a wrong mark becomes a ticket, never an edit made here.

## Start it

```bash
bash curation-review/run.sh                  # backend :8787 (FastAPI) + frontend :5173 (Vite); Ctrl-C stops both
curl -s http://127.0.0.1:8787/api/ready      # wait for "ready": true (the warm-up loads graph, registry, queue)
```

Open http://127.0.0.1:5173. Both servers bind 127.0.0.1 only; `PORT` / `CURATION_VITE_PORT` move the ports (a second copy
beside the owner's). `run.sh` refuses a port already listening. By hand: `bash curation-review/backend/run.sh`, then
`npm install && npm run dev` in `frontend/`. To rehearse on a copy: `CURATED_ROOT=<copy made by
pipeline.common.curated.make_root>`.

## What is where

| path | what |
|---|---|
| `backend/` | FastAPI: `app.py` (routes), `reuse.py` (the served build and its caches), `writes.py` (every write: backup, then all-or-nothing commit), `write_through.py`, `checks.py`, `dfo.py`, `inseason.py` |
| `frontend/` | Vite + React + TypeScript screen (its README); no unit runner, `npx tsc -p tsconfig.json --noEmit` |
| `API.md` | the route table, GENERATED by `curation-review/api_routes.py --write`; regenerate it in the same commit as a route change (AGENTS W46); never edit by hand |
| `pipeline/regs/review/` | the server side as a library: marks and their fingerprints (`marks.py`, `fingerprint.py`), the apply paths that put a mark into its final curated file (`apply.py`, `apply_proposals.py`), the queue order (`tiers.py`), pre-checks (`precheck.py`), vintage (`vintage.py`), the DFO queue (`dfo.py`) |

## What it reads and writes

- Reads: `data/curated/regulations/synopsis/region-*.json` (the entries), `data/curated/waters/cuts.json`, the served atlas
  and reach run (`data/generated/atlas/full`, the bundle), the synopsis PDF.
- Writes the OWNER'S marks: `data/curated/review/marks.jsonl` (append-only; AGENTS A8: nobody edits, reorders, regenerates or
  deletes a line, only this app appends). A saved mark's domain is then applied to its final curated file by
  write-through (`write_through.py`: sloughs, names, tidal at once; dfo, entries, splits in the background, one commit per proposal),
  and a shrink of more than 10 rows is refused (AGENTS W46). Backups of what it overwrites:
  `data/generated/regs/entries_backup/curation-review/`. In-season matches go to `data/curated/inseason/notice_waters.json`.
- No endpoint starts a process; it never builds or promotes an atlas. Rebuilds are the owner's, run from a terminal.

Rules: AGENTS 65-68 (a mark names one vintage; one write, a mark; one queue order; a closed area is its own place).
